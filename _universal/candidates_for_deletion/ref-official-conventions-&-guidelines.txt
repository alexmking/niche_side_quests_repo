> NOTE: the below prefix and path stuff has been pretty well thought out so be careful changing stuff that you think doesnt make much sense at the surface 
    bc there's very likely a good reason it's that way
        EX: using the ,. prefix is easy to remember bc the keys are right next to each other
        ALSO: using the same prefix for the full path defintions allows us to more casually/quickly search for a directory without needing to include any directories leading up to it, which is def a big perk, bigger perk than it sounds on its face.
            > also, allows us to jump to each sub-section of a section by simply searching for 


> The 2nd line of the h2 and h3 headers is for the full 'path' concept, similar to file directories except the dash / is replaced wit hthe prefix ,;
    > by having these full path lines,
